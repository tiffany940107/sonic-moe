# M0-M6 Completion Audit

This audit maps every 0902 plan phase to code, tests, measurements, and the
retention/stop decision. “Complete” means the phase reached its stated gate;
it does not mean every experiment was promoted to the default path.

## Formal protocol audit

- All admitted E0 groups have 20 warmups, 100 timed iterations, and three
  independent process restarts.
- E0 uses the maximum four-rank CUDA-event interval; tables use the median of
  restart percentiles.
- The A/B balanced matrix covers m/rank 8,192, 16,384, 32,768, and 46,080 for
  legacy Sonic, prior fused Sonic, final transport-workspace Sonic, and latest
  block-scale.
- MegaMoE has reporting-only p95/p99 remeasurement at 8K/16K. Its 32K/46,080
  signed-INT32 extent failures have explicit status records and no latency.
- The B-node common unbalanced matrix covers six supplied traces plus the
  isolated single-hot trace on the same trace hashes.
- Every admitted Sonic/block-scale result passes C4. Correctness-invalid
  block-scale attempts are status-only. MegaMoE latency is admitted under its
  separately recorded strict common-trace gate.
- `completion-audit.json`, generated by `audit-summary.py`,
  fails closed on missing restarts, tail percentiles, correctness, trace-hash
  mismatch, or required status records.

## Explicit gate exceptions and negative results

M2 did not meet its standalone 50% stage/3% E0 gate: its main value is direct
blocked-scale metadata production for M3. It remains internal to the retained
M3 path and is not advertised as an independent win. The final EP transport
workspace adds only 0.31% geometric p50 improvement across the eight balanced
cells; it is retained for zero-allocation determinism and has no formal
regression, not as a standalone latency claim.

M4 was stopped before porting the upstream FC12 scheduler into Sonic. This is
the plan’s pre-port stop gate: both the exact-shape upstream measurement and
the optimistic tile-resident lower bound were already worse than Sonic’s safe
separate kernels. No document claims that a Sonic FC12 implementation was
completed.

## Remaining external resource blocker

Symmetric cross-NUMA 2+2 formal matrices cannot currently allocate the 8K
expert bank because an unrelated workload occupies the second NUMA GPU group
on both shared nodes. Both attempts are recorded as
`resource_blocked_external_gpu_memory`; no process was terminated and no
same-NUMA result was substituted. The topology-safe scripts are ready to rerun
unchanged when that external memory is released. The operational campaign has
a resumable locked full-matrix runner; public entry point
`run-cross-numa-when-ready.sh` applies the same rule that the top two devices in
each NUMA group have at least 60,000 MiB free and returns 75 without starting a
benchmark when the resource gate fails. The latest gate observed only 4,083
MiB on A and 1,129 MiB on B.
This is the only plan item without a formal runnable result.
